## 데이터와 빌드

서비스 루트에서 fixture 검사를 실행한다.

```sh
python3 scripts/check_mock_data.py
```

프런트는 `frontend/`에서 `npm ci`, `npm test`, `VITE_APP_MODE=mock VITE_BASE_PATH=/bigcontest/ npm run build`를 실행한다. 백엔드는 [배포 문서](DEPLOYMENT.md#로컬-python-api)의 설치 후 `backend/`에서 `.venv/bin/python -m pytest -q`를 실행한다. 현재 테스트 파일은 백엔드 `tests/test_graph.py`, `tests/test_api.py`, `tests/test_store.py`에 있다.

- [ ] `npm ci`가 커밋된 lockfile로 설치되고 프런트 빌드가 성공한다.
- [ ] `/bigcontest/` base로 만든 산출물에서 새로고침·JS·CSS·GeoJSON·dataset 로딩이 성공한다.
- [ ] 모든 지리 객체가 Polygon/MultiPolygon이며 EPSG:4326 좌표와 `code`, `name`, `district`를 가진다.
- [ ] GeoJSON과 dataset의 `code`에 중복이 없고 표시 대상의 코드가 서로 대응한다. 코드 문자열을 숫자로 바꾸어 선행 0을 잃지 않는다.
- [ ] 지리 경계 출처·기준 시점·라이선스 및 가공 기록을 확인한다. 합성 수치와 경계의 실재성을 혼동하지 않는다.
- [ ] 유효한 점수는 0~100이며 시연 기준인 40·70 경계에서 분류가 일치한다. 자료 부족은 null/unknown이다.
- [ ] `dist/mock/` 등 공개 산출물에 연구 원본·개인정보·비밀키가 없다.

실행 명령은 [DEPLOYMENT.md](DEPLOYMENT.md)의 로컬 확인 절차와 아래 구현별 항목을 사용한다. 빌드 성공은 타입·번들 검사의 증거이며 화면과 시나리오의 정상 동작까지 증명하지 않는다.

## 다섯 시나리오 공통 기준

같은 동을 선택해 **브라우저 mock**과 **API mock**에서 각각 검사한다. API mock은 실제 LangGraph를 사용하지만 실제 LLM·학습 모델은 없다. 두 경로의 위험 점수·위험 단계·보류 여부·정책 의미를 비교하되 실행 ID, 완료 시각, 문장·단계 ID의 완전 일치까지 요구하지 않는다.

| 입력 | 합격 기준 | 실패 예 |
| --- | --- | --- |
| `normal` | 원래 점수, `completed`, 유효한 가상 정책 1~3개 | 근거 없이 원래 점수 변경, 실제 정책으로 표시 |
| `risk_spike` | `min(99, 원래 점수+30)`, 점수에 맞는 등급, 변화 조사 단계 | 100 초과, 이전 점수 그대로, 변화 조사 없음 |
| `missing_data` | `risk_score=null`, `unknown`, `held`, 정책 `[]`, 누락 경고 | 0점/정상 처리, 정책 검색 계속 수행 |
| `expired_policy` | 만료 후보 제외와 재검색 단계, 결과에 유효 후보만 포함 | 만료 후보를 최종 추천, 재검색 없는 정상 경로 |
| `no_policy` | 정책 `[]`, 정책 공백·담당자 확인 경고, 유한 단계 내 종료 | 후보를 임의 생성, 반복 검색 종료 안 됨 |

정책 유효성의 기준 시각은 fixture의 `as_of`와 서버 구현을 확인해 일관되게 적용한다. 현재 날짜가 바뀌었다고 시연 fixture 결과가 임의로 바뀌면 재현성이 깨지므로 기준을 기록한다.

## API 계약과 실패 처리

- [ ] `GET /api/health`가 `{status:"ok", mode:"mock", graph:"langgraph"}`를 반환한다.
- [ ] `GET /api/districts`가 dataset 전체 구조와 명시적 mock 표시를 반환한다.
- [ ] `POST /api/runs`가 계약에 맞는 전체 결과를 한 번에 반환한다. SSE나 background job이 구현됐다고 주장하지 않는다.
- [ ] 반환된 `run_id`로 `GET /api/runs/{run_id}`를 조회하면 저장된 결과가 나온다.
- [ ] 없는 동 코드·잘못된 시나리오·없는 실행 ID는 적절한 4xx로 처리된다. 오류가 성공 결과로 바뀌지 않는다.
- [ ] `APP_MODE=live`는 명시적 미구현 오류 또는 시작 차단으로 처리된다. mock fallback이 없다.
- [ ] API 모드의 주소 누락, 서버 중단, 4xx/5xx, 잘못된 응답이 화면 오류로 드러난다.
- [ ] CORS가 실제 프런트 origin에 대해 허용되고 무관한 origin에 무분별하게 열려 있지 않다.
- [ ] 서버 재시작 후 메모리 기록 소실을 확인하고 그 제한을 시연 설명에 포함한다.
- [ ] `RUN_STORE_MAX` 초과 시 오래된 결과가 제거되고 `RUN_STORE_TTL_SECONDS` 이후 만료되는지 검사한다. 반환 객체를 바꿔도 저장 원본이 바뀌지 않는지 확인한다.

health 검사는 연결과 프로세스 상태를 확인하는 검사다. 다섯 시나리오, 정책 제외, 화면 오류 처리를 대신하지 않는다.

## 사용자 화면

- [ ] 모든 화면에서 합성 데이터·가상 정책임을 확인할 수 있고 위험 지수를 확률로 표현하지 않는다.
- [ ] 지도 동 선택과 목록 선택이 동일한 상세 패널을 갱신한다. 선택 동을 바꾸면 이전 실행 결과가 새 동의 결과처럼 남지 않는다.
- [ ] 검색과 필터의 초기 상태·결과 없음·초기화가 동작한다.
- [ ] 데이터 로딩·오류·자료 부족·정책 없음이 서로 구분된다.
- [ ] 실행 중 중복 클릭을 제한하고 시나리오·동 변경 시 결과 혼선을 방지한다.
- [ ] 점수 등급을 색과 텍스트로 함께 표시한다. 회색 자료 부족을 정상으로 오해하지 않는다.
- [ ] 키보드만으로 검색·필터·동 선택 대체 목록·시나리오·실행 버튼을 사용할 수 있고 포커스가 보인다.
- [ ] 390px 모바일과 1440px 데스크톱에서 지도·상세·정책·실행 단계가 겹치거나 가로로 잘리지 않는다.
- [ ] 브라우저 콘솔 오류와 실패한 필수 네트워크 요청이 없다. 외부 지도를 사용한다면 해당 요청·출처 표시도 확인한다.

## 배포 직후 확인

- [ ] Actions의 검사·빌드·배포 성공을 각각 확인하고 공개 URL에서 직접 실행한다.
- [ ] `/bigcontest/`와 `/bigcontest/mock/dataset.json`, `/bigcontest/mock/districts.geojson`에 접근할 수 있다.
- [ ] 공개 배포의 mock은 API 서버 없이 동작한다. API 배포를 선택했다면 해당 서버와 HTTPS·CORS를 함께 확인한다.
- [ ] 시크릿 창 또는 캐시를 지운 브라우저에서 새 버전이 보인다.
- [ ] 마지막 정상 커밋, 롤백 경로, 현재 미구현 범위를 기록한다.

## 결과를 표현하는 방법

“문서 작성”, “정적 코드 확인”, “로컬 빌드 성공”, “API 테스트 성공”, “브라우저 확인”, “공개 배포 확인”을 구분한다. 실행하지 않은 항목은 **미실행**, 환경 때문에 못 확인한 항목은 **차단 사유**, 발견된 결함은 **재현 입력과 기대·실제 결과**를 기록한다. 실제 모델 성능이나 서비스 운영 안정성을 이 체크리스트의 통과 결과로 확대 해석하지 않는다.
